# Mail Sort

Система автоматической сортировки корпоративной почты. Читает письма из `inbox/`, определяет категорию каждого письма и раскладывает по папкам `output/<категория>/`. Ведёт лог и выводит статистику.

Проект хакатона по предмету «Технологии программирования»

## Как устроено

Обработка письма идёт в три этапа.

Парсер (`src/parser.py`) читает файл и возвращает объект `Email` с полями: отправитель, тема, дата, текст. Поддерживает txt, json и файлы без расширения. Заголовки распознаёт на русском, английском и транслите. Бинарные и битые файлы не парсятся, но не роняют программу, они помечаются как непарсящиеся.

Классификатор (`src/classifier.py`) определяет категорию письма по ключевым словам. Категорий девять: spam, incidents, hr, access_requests, hardware, finance, documents, external, info. Правила проверяются по приоритету, первое совпадение побеждает. Если ни одно правило не сработало, то письмо уходит в `unclassified`. Письма с расхождением темы и тела (тема `[CRITICAL]`, тело — отчёт мониторинга) определяются по содержимому тела.

Роутер (`src/router.py`) копирует письмо в папку категории (оригинал в `inbox/` не трогается), логирует операцию и считает статистику.

Точка входа – `src/main.py`. Обоснование категорий — в `docs/categories.md`.

## Установка

Нужен Python 3.9+.

    pip install -r requirements.txt

## Запуск

    ./run.sh

или напрямую:

    python3 -m src.main

Режим предпросмотра без копирования файлов:

    python3 -m src.main --dry-run

## Тесты

    python3 -m pytest -v

Тесты используют собственные письма из `tests/fixtures/` и не зависят от `inbox/`. Покрыты все три модуля и граничные случаи: пустой файл, битый JSON, бинарник, письмо без совпадений.

## Структура

    mail-sort/
    ├── inbox/     входящие письма
    ├── output/    результат (создаётся при запуске)
    ├── logs/      логи обработки
    ├── src/       исходный код
    ├── tests/     тесты и фикстуры
    ├── docs/      документация
    └── run.sh     скрипт запуска

## Известные ограничения

Классификатор на правилах иногда ошибается на письмах с пересекающимися признаками (например, «не работает принтер» попадает в incidents вместо hardware). Ключевые слова зашиты в коде — их можно вынести в конфиг для настройки без правки кода.
